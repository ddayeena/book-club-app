## Контракти ключових компонентів

| Компонент          | Вхідні властивості                | Домовленість                                            |
|--------------------|-----------------------------------|---------------------------------------------------------|
| AppLayout          | title, links, children            | Створює спільну оболонку з одним main                   |
| Section            | id, title, children               | id унікальний у поточному документі                     |
| ClubList           | clubs                             | Масив клубів; порожній масив допустимий                 |
| ClubCard           | club                              | Коректний запис із полями моделі Л 1.1                  |
| ReadingStatusBadge | currentBook                       | Рядок або null, без зміни даних                         |
| JoinPage           | club                              | Запис або відсутнє значення для порожнього результату   |
| FormField          | id, label, hint, children         | Вкладене поле має відповідний id і зв'язок із підказкою |
| JoinFormPreview    | idPrefix, clubName                | Унікальний префікс; макет без збереження                |
| AppButton          | children, type, variant, disabled | variant: primary або secondary                          |

## Обґрунтування ключових рішень

1. ReadingStatusBadge винесено з ClubCard в окремий предметний компонент,
   бо те саме правило статусу книги повторно використовується на сторінці
   заявки (JoinPage) — зміна підпису тепер відбувається в одному місці й
   одразу відображається скрізь.

2. Section застосовано двічі з різним вмістом (опис і каталог) на
   HomePage, і ще раз на JoinPage — це повторне використання композиції
   через children, а не копіювання розмітки заголовка секції.

3. FormField і AppButton винесено як спільні UI-компоненти, не прив'язані
   до книжкових клубів: вони знають лише про підпис/підказку/варіант
   кнопки, а не про заявки чи клуби — це дозволяє використати їх і в
   майбутніх формах (пропозиція книги, голосування) без змін.




## Керування станом (Л 2.1)

### Карта власників стану

| Значення           | Природа                   | Власник                                   |
|--------------------|---------------------------|-------------------------------------------|
| clubs              | Початкові предметні дані  | data/clubs.js, підключено на рівні App    |
| detailsOpen        | Локальний стан інтерфейсу | Конкретна ClubCard                        |
| query, readingOnly | Стан інтерфейсу каталогу  | Хук useClubFilters, викликаний у HomePage |
| selectedId         | Спільний стан вибору      | ClubSelectionProvider                     |
| draft              | Незбережені поля заявки   | Поточний екземпляр JoinPage               |
| visibleClubs       | Похідний список           | Обчислюється в useClubFilters             |
| selectedClub       | Похідний запис            | Обчислюється в ClubSelectionProvider      |

### Обґрунтування засобів керування станом

| Потреба                       | Засіб                               | Обґрунтування                                                     |
|-------------------------------|-------------------------------------|-------------------------------------------------------------------|
| Розгортання опису клубу       | Локальний useState                  | Потрібне лише одному екземпляру картки                            |
| Пошук і фільтр "лише читають" | Стан сторінки через власний хук     | Параметри потрібні фільтрам і списку одного сценарію              |
| Поля та підсумок чернетки     | Підняття до JoinPage                | Форма й підсумок мають бачити той самий об'єкт                    |
| Вибір між каталогом і заявкою | Context API (ClubSelectionProvider) | Один ідентифікатор узгоджує дві незалежні гілки дерева            |
| Видимі клуби й лічильники     | Звичайні обчислення під час рендеру | Значення повністю визначаються поточними даними й фільтрами       |
| Заголовок вкладки             | useEffect                           | Синхронізація із зовнішньою властивістю браузера (document.title) |

### Область провайдера

ClubSelectionProvider огортає <Outlet /> усередині AppLayout, тому діє на
всі маршрутні сторінки одразу (HomePage, ClubsListPage, ClubDetailsPage,
сторінки розділу requests) — а не лише на окремі контейнери, як було
до Л 2.2. SiteHeader, MainNav і підвal залишаються поза областю
контексту, оскільки не потребують вибору клубу. Оскільки провайдер
монтується один раз у спільній оболонці й не демонтується під час
переходів між дочірніми маршрутами, останній вибір клубу переживає ці
переходи (але скидається при перезавантаженні сторінки).

### Контракти подій

- onSelect(id) — ClubCard → ClubList → HomePage → CatalogContainer → провайдер
- onQueryChange(text), onReadingOnlyChange(flag) — ClubFilters → HomePage (хук)
- onMotivationChange(text), onWantsRemindersChange(flag) — JoinForm → JoinPage
- onReset() — скидання фільтрів (HomePage) або чернетки (JoinPage), окремі дії
- onClearSelection() — JoinPage → JoinContainer → провайдер (clearSelection)


## Маршрутизація (Л 2.2)

### Дерево маршрутного вмісту

AppLayout (ClubSelectionProvider, Outlet)
  HomePage
  CatalogContainer → ClubsListPage        (/clubs)
  ClubDetailsPage                         (/clubs/:clubId)
  RequestsLayout (Outlet)                 (/requests)
    RequestsPage                          (index)
    RequestCreatePage → JoinPage          (/requests/new?clubId=...)
    RequestEditPage → JoinPage            (/requests/:requestId/edit)
  NotFoundPage                            (*)

### Джерела стану після додавання маршрутизації

| Значення                       | Де зберігається               | Після перезавантаження  |
|--------------------------------|-------------------------------|-------------------------|
| Відкрита сторінка й id         | Шлях URL                      | Відновлюється           |
| Пошук і фільтр "читають"       | Query parameters (q, reading) | Відновлюється           |
| Клуб нової заявки              | Query parameter clubId        | Визначається з адреси   |
| Останній явний вибір клубу     | ClubSelectionProvider         | Скидається              |
| Введення у формі (draft)       | Локальний стан JoinPage       | Скидається              |

### Рішення
1. ClubSelectionProvider перенесено в AppLayout: він лишається змонтованим при переходах між дочірніми сторінками, тому останній вибір не губиться.
2. Фільтри каталогу читаються з URL (useSearchParams), дубльованих useState немає; контракт useClubFilters збережено.
3. JoinPage став спільним редактором, а перевірку клубу виконують RequestCreatePage і RequestEditPage; key за ідентичністю запису не змішує чернетки.
4. JoinContainer прибрано: його роль виконують маршрутні сторінки.
5. Чернетка живе, доки відкрита сторінка редактора; після виходу, зміни клубу чи запису або перезавантаження скидається.


## Форми, валідація та CRUD заявок (Л 3.1)

### Модель заявки та правила

| Поле           | Правило                                                  |
|----------------|----------------------------------------------------------|
| id             | Стабільний, створюється операцією додавання              |
| clubId         | Посилання на наявний клуб каталогу                       |
| motivation     | Обов'язковий текст, 10–500 символів без крайніх пробілів |
| weeklyHours    | Обов'язкове ціле число від 1 до 8                        |
| wantsReminders | Логічне; обов'язково true при weeklyHours > 4            |

### Власники даних і чернетки

| Дані                       | Власник                                | Коли змінюються                                 |
|----------------------------|----------------------------------------|-------------------------------------------------|
| Довідник клубів            | data/clubs.js                          | Не редагується в цій роботі                     |
| Колекція заявок            | RequestsProvider                       | Після успішного створення/оновлення/видалення   |
| Чернетка                   | Поточний JoinPage                      | Під час введення й відновлення початкових полів |
| Помилки й ознаки перевірки | Поточний редактор (touched, attempted) | Після взаємодії та спроби збереження            |
| Пошук, фільтр, порядок     | URL сторінки списку заявок             | Після зміни параметрів q/reminders/sort         |
| Видимі заявки              | Обчислення в useRequestFilters         | З поточної колекції та параметрів               |

### Контракти операцій

| Операція              | Вхід                 | Успіх                          | Відмова                           |
|-----------------------|----------------------|--------------------------------|-----------------------------------|
| createRequest         | Поля заявки          | { ok: true, record }           | Помилки полів                     |
| updateRequest         | Ідентифікатор і поля | { ok: true, record }           | Помилки полів або відсутній запис |
| deleteRequest         | Ідентифікатор        | { ok: true }                   | Відсутній запис                   |
| Перегляд за маршрутом | Ідентифікатор        | Знайдений запис                | Сторінка відсутнього запису       |


## Асинхронні сервіси та інтеграція (Л 3.2)

### Схема залежностей

Сторінки та форми → RequestsProvider/хуки → requestService → Mock або REST
адаптер → Локальне сховище (localStorage) або зовнішнє API.

### Контракт сервісу заявок

| Метод                   | Успіх                                  | Відмова                                |
|-------------------------|----------------------------------------|----------------------------------------|
| getAll({ signal })      | Масив заявок, зокрема []               | Виняток сервісу або скасування         |
| getById(id, { signal }) | Одна заявка                            | NOT_FOUND для відсутнього запису       |
| create(input)           | Повний збережений запис із id          | Помилка перевірки, запису чи з'єднання |
| update(id, input)       | Повний оновлений запис із тим самим id | Зокрема NOT_FOUND                      |
| delete(id)              | undefined після підтвердження          | Зокрема NOT_FOUND                      |

### Перевірені режими

- mock (localStorage, ключ bookclub.requests.v1) — перевірено повністю: створення,
  перегляд, редагування, видалення, повтор після відмови, збереження між
  перезавантаженнями.
- api (fetch-адаптер) — підготовлено за контрактом вище [ще не підключено до реального сервісу].

### Синхронізація

Після успішного запису провайдер застосовує запис, повернений сервісом,
а не повторне читання всієї колекції. Явне "Оновити дані" перечитує джерело.
Застарілі відповіді читання відхиляються за номером версії; активний запис
блокує паралельне читання.
