# Фактично виконані перевірки

Цей журнал відділяє повідомлений стан deployment, локальні автоматичні перевірки та ще не підтверджені серверні сценарії. Наявність тестового файла або чекліста не означає його проходження.

## Підтверджено власницею

ReadHub працює на Vercel, нові демонстраційні дані успішно створені, новий адміністратор працює. Це повідомлення власниці під час фінального очищення репозиторію; незалежної перевірки deployment чи БД у цій роботі не проводилося.

## Локальний прогін після очищення документації

Виконано 13 листопада 2026 року, із кореня репозиторію у Windows; Supabase не підключався.

| Команда | Фактичний результат |
| --- | --- |
| `npm.cmd run lint` | Успішно, exit code 0; ESLint не повідомив помилок |
| `npm.cmd run test:run` | Успішно: 60 файлів, 527 тестів; Vitest 5.0.4, jsdom |
| `npm.cmd run build` | Успішно, exit code 0; Vite 8.3.0, 297 трансформованих модулів |

Build залишив попередження про чанк понад 500 кБ: початковий index JS — 514,64 кБ, gzip 146,30 кБ. Це попередження, не помилка збірки. Код і поріг попередження під час очищення не змінювалися. Vitest також вивів інформаційну пораду щодо витрат на створення jsdom; збоїв тестів не було.

На момент попереднього очищення додатково перевірено локальні посилання в усіх 18 Markdown-файлах і шаблони можливих секретних ключів, паролів та приватних email: проблем не виявлено. Це локальна перевірка документації, не аудит облікових записів чи віддалених налаштувань.

Порівняння SHA-256 до/після підтвердило незмінність `src/` разом із frontend-тестами, 12 міграцій, 10 SQL-тестів і 2 сценаріїв конкурентності, `vercel.json`, пакетних маніфестів, `.env.local` та актуальних demo-скриптів/SQL. `dist/` оновлено командою build як ігнорований артефакт; deployment не виконувався.

## Серверні сценарії без підтвердженого повного прогону

- Усі pgTAP-набори `supabase/tests/*.test.sql`.
- Обидва isolationtester-сценарії `supabase/tests/*_concurrency.spec`.
- Повна матриця RLS через реальні JWT різних ролей, реальні Storage-завантаження й конкурентні зміни.

Попередні документи містили повідомлення про ручні перевірки сповіщень/Cron та обговорень; вони є історичними повідомленнями, а не протоколом повного SQL-прогону. У межах фінального очищення їх не повторювали. Поточні правила зібрані в [backend-архітектурі](backend-architecture.md), серверні набори й порядок їх виконання — в [SQL-тестах](../supabase/tests/README.md). Опис правил і наявність тестів не підтверджують їх проходження.
