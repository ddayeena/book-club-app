# Завантаження маршрутів ReadHub

`App.jsx` використовує React.lazy через `routes/lazyPage.js`. Пов’язані сторінки
зібрано у сім груп: адміністративні, зустрічі, обговорення, заявки, персональні,
книги/голосування та форми клубу/авторизації. Головна, каталог, деталі клубу,
невідома сторінка й перевірки доступу залишаються статичними.

Адміністративна група містить також AdminLayout. RequireAdmin виконується перед
рендерингом цієї групи: відмова в доступі не запускає її імпорт.

Suspense розміщено всередині main основного й адміністративного макетів.
Навігація та провайдери не входять у цю межу. Для першого завантаження самого
AdminLayout є окрема захищена межа. Усі fallback мають доступний стан
«Завантаження сторінки…». Наявні відмінності провайдерів профілю та каталогу
збережено.

Помилка динамічного імпорту позначається як PageChunkError і потрапляє до
ErrorBoundary. Він пояснює можливу проблему мережі або застарілу версію файлів
після деплою та пропонує ручне оновлення сторінки. Це повторно завантажує HTML
і актуальні URL чанків; автоматичних перезавантажень чи нескінченних повторів немає.
Простий повторний рендер React.lazy не використовується як спосіб відновлення:
невдалий імпорт кешується.

## Порівняння production-збірок

Нижче — історичні вимірювання під час впровадження lazy-маршрутів, а не розміри
останнього deployment чи поточної збірки. Поточний локальний результат і попередження
наведено в [журналі перевірок](verification.md).

Розміри в десяткових кБ; gzip — значення зі звіту Vite.

| Показник | До | Після |
| --- | ---: | ---: |
| Початковий JS, включно з modulepreload | 695,21 | 563,26 |
| Початковий JS gzip | 192,74 | приблизно 163,88 |
| Усі JS-файли | 695,21 | 701,33 |
| Сума gzip усіх JS-файлів | 192,74 | приблизно 206,88 |
| Найбільший JS-файл | 695,21 | 514,27 |

Початкове завантаження — index.js (514,27 кБ) і спільний чанк
PageHeading (48,99 кБ). Назва спільного чанка автоматична: він містить також
спільні залежності. Адміністративний чанк (32,82 кБ, gzip 9,01 кБ) та решта
маршрутних груп не включені до modulepreload початкового HTML.

Зменшення початкового JS становить близько 19%, gzip — 15%. Загальний обсяг
трохи зріс: мета розділення — відкласти непотрібний код, а не зменшити весь
застосунок. Для прямого відкриття lazy-маршруту додатково потрібна його група.
Попередження Vite про index.js понад 500 кБ залишається; поріг не змінено.

На хостингу все ще потрібен звичайний SPA fallback до index.html для вкладених
URL. Після деплою слід перевіряти пряме відкриття, F5 та сценарій зі старою
вкладкою. Ця зміна не налаштовує кешування або хостинг і не змінює Supabase.
