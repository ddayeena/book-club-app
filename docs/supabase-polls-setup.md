# Блок 3Б: голосування за наступну книгу

## Застосування

Підготовлено `supabase/migrations/202611110006_book_polls.sql`. Її не застосовано автоматично.
Міграції 001–005 залишаються незмінними. Нових бібліотек, ключів чи платних API немає.

1. Спочатку перевірте міграцію та тести в окремому одноразовому Supabase з 001–005.
2. Перегляньте 006 і застосуйте її вручну в цьому тестовому проєкті. Уся міграція — одна транзакція.
3. Виконайте `supabase/tests/book_polls.test.sql` та попередні SQL-тести в тестовій БД з pgTAP.
   Файл створює фіктивні auth.users, членство та книги, змінює час завершення тестових голосувань
   і ролі фіктивних користувачів; усе завершується ROLLBACK. На основному проєкті його не запускайте.
4. Після перевірки створіть резервну копію основної БД та коротко призупиніть записи під час
   ручного застосування 006 і розгортання нового клієнта. Перезавантажте старі вкладки.
5. Не додавайте `private` до Exposed schemas. Використовуйте наявні Auth і publishable key;
   налаштування `.env.local` не змінюються. Нові Storage buckets або Realtime-публікації не потрібні.

Новий клієнт книжкової полиці потребує RPC `get_club_book_flags` із 006: розгортайте його після міграції.
Дані клубів, книг, заявок і членства не переносяться та не видаляються.

## Структура та доступ

- `book_polls`: клуб, назва, серверні дати створення/завершення, фіксація переможця,
  скасування з причиною, одноразове споживання позначки наступної книги.
- `book_poll_options`: незмінні книги клубу, порядок, знімки назви й автора для історії.
- `book_votes`: один запис `(poll_id, user_id)`; зміна вибору оновлює його. FK посилається на
  профіль, а не членство: вихід не видаляє голос і повторний вступ не створює другий.
- Частковий унікальний індекс за club_id враховує тільки `finalized_at IS NULL AND cancelled_at IS NULL`.
  Умова не залежить від часу: прострочене голосування блокує наступне до явного рішення власника.
- Усі три таблиці мають RLS, прямі записи клієнтам заборонені. Учасники й власник читають результати;
  admin може їх переглядати, але не голосує без членства й не отримує права власника.
  Архів доступний за наявними правами читання архівного клубу. Сирі голоси видно тільки їх автору.
- Привілейовані функції розміщені у private з порожнім search_path, перевіркою активного акаунта
  та вузькими EXECUTE. Публічні обгортки — SECURITY INVOKER. Службові lock-функції клієнтам закриті.
- RPC результатів повертає лише кількості та власний вибір. Імен, адрес і списків виборців немає.
  Публічний RPC позначок полиці розкриває тільки ID книги та два логічні значення.

## RPC та конкурентні операції

`create_book_poll`, `cast_book_vote`, `finalize_book_poll`, `cancel_book_poll`,
`get_book_poll`, `list_book_polls`, `get_club_book_flags`.

Мутації блокують спочатку клуб, потім голосування. Це той самий клубний замок, що в операціях
членства, книг і архівування. Час голосу перевіряється через clock_timestamp() після очікування
блокувань. Жоден параметр не задає автора голосу чи власника; варіант і переможець перевіряються
в межах конкретного голосування. Унікальний ключ захищає від додаткових голосів.

Незавершені варіанти не можна редагувати чи починати читати навіть після ends_at. При фіксації
дозволено лише лідера; за нульових результатів усі варіанти рівні. Переможець залишається planned.
Початок його читання встановлює selection_consumed_at, і повернення до planned не відновлює позначку.
Показується переможець останнього зафіксованого голосування; до старіших переможців автоматичного
повернення немає. Архівування атомарно скасовує незавершене голосування і зберігає голоси.

## Ручна перевірка

- Власник: створити голосування з двома planned-книгами; перевірити блокування редагування/читання,
  заборону другого голосування, дострокової фіксації та підтвердження скасування (у тому числі клавіатурою).
- Два учасники: проголосувати, змінити вибір, F5, вийти та вступити повторно; сума голосів не зростає
  від повторного вступу. Власник голосує як учасник. Сторонній користувач і admin без членства — ні.
- Завершення: єдиний лідер, нічия, нуль голосів, неправильний переможець, повторна фіксація,
  запізнілий голос. Час на пристрої не змінює серверного дозволу.
- Наступна книга: фіксація не змінює статус, старт прибирає позначку назавжди, історія зберігає
  знімок старої назви після редагування книги.
- Архів: незавершене голосування скасовано, книги й голоси незмінні; гість не отримує історію.
- Регресії: каталог, створення/редагування клубу, заявки, членство та відновлення Auth-сесії.
- Мережа: помилка/повторне завантаження, подвійний клік, прямий URL, F5, вузький екран.

Окремо перевірте двома SQL-сесіями **тільки в тестовій БД**: у першій транзакції заблокуйте рядок
тестового клубу FOR UPDATE; у другій від імені учасника викличте cast_book_vote до короткого ends_at;
відпустіть перший замок після ends_at. Голос, що дочекався замка запізно, має бути відхилений.
Аналогічно перевірте пари голос/вихід, два створення, фіксація/скасування, старт книги/створення
та голос/архівування. Послідовні pgTAP-тести не замінюють таку конкурентну перевірку.

Перевірки фронтенду: `npm.cmd run lint`, `npm.cmd run test:run`, `npm.cmd run build`.
Локальні unit-тести не є підтвердженням виконання SQL чи налаштувань віддаленого Supabase.
