# ReadHub: вимоги, завершений обсяг та історія

## Призначення

Курсова робота — вебплатформа книжкових клубів. Вона об’єднує каталог, вступ до спільноти, спільне читання, вибір наступної книги, зустрічі та обговорення. Реалізація: React + Vite, Supabase PostgreSQL/Auth/Storage; frontend розгорнуто на Vercel.

## Реалізовані сценарії

| Роль | Можливості |
| --- | --- |
| Гість | Перегляд активних клубів і книжкових полиць, пошук, реєстрація |
| Користувач | Профіль, заявки, створення власного клубу, особисті сповіщення |
| Учасник | Голосування, приватні зустрічі та обговорення свого клубу, вихід |
| Власник | Керування клубом, рішення за заявками, книги, голосування, зустрічі, модерація |
| Адміністратор | Статистика, перегляд користувачів/клубів, блокування та модерація в межах серверних прав |

Роль admin не замінює членство або власність для кожної операції: наприклад, сама по собі не дозволяє редагувати чужу полицю чи планувати чужі зустрічі. Конкретні правила описані в [backend-архітектурі](backend-architecture.md).

## Предметна модель

Auth-акаунт → профіль і доступ; клуб → членства, заявки, книги, голосування, зустрічі та теми; тема → коментарі. Системні сповіщення стосуються заявок і зустрічей. Книжкові записи належать клубу; єдиного зовнішнього каталогу книг немає. Читання має planned/current/completed, заявки — pending/approved/rejected/cancelled. Архівування зберігає історію, відновлення не відкриває скасовані події повторно.

## Межі реалізації

Не реалізовано передачу власності клубу, інтеграцію пошуку книг із зовнішнім API, email/push/Telegram-доставку нагадувань, вкладені відповіді на коментарі та відновлення видаленого тексту обговорень. Листи підтвердження реєстрації обслуговує Supabase Auth. Призначення admin виконує довірений оператор Dashboard.

## Історичні етапи

1. Навчальний локальний каталог, композиція компонентів, стан, URL-фільтри та форми.
2. CRUD заявок, mock/REST-адаптери й тестування.
3. Перехід на Supabase Auth та серверні клуби/заявки: міграції 001–004.
4. Книги, голосування, адмінпанель і аватари: 005–008.
5. Зустрічі, відновлення клубів, сповіщення та обговорення: 009–012.
6. Lazy-завантаження маршрутів, Vercel і нове демонстраційне наповнення.

Опис локального каталогу, Auth у localStorage й перемикання mock/api стосується історії. Поточну архітектуру визначає [окремий документ](component-architecture.md), а не попередні лабораторні схеми. Частина адаптерів збережена для тестів.

## Фактично підтверджений стан

Власниця підтвердила роботу ReadHub на Vercel, успішне створення нових демонстраційних даних і роботу нового адміністратора. Це не означає автоматичного проходження всіх сценаріїв доступу, Storage або конкурентності. Локальні команди й статус SQL-перевірок наведено в [журналі перевірок](verification.md). Налаштування нового середовища — в [інструкції Supabase](supabase-setup.md).
