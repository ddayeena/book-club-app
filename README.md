# ReadHub — платформа книжкових клубів

Курсова робота на React + Vite та Supabase (PostgreSQL, Auth, Storage). Frontend розгорнуто на Vercel. За підтвердженням власниці, демонстраційні дані створені й новий адміністратор працює. Це підтвердження експлуатації, а не результат автоматичного тестування віддаленої БД.

## Реалізовано

- Публічний каталог із пошуком і фільтрами, деталі клубів і книжкові полиці.
- Реєстрацію з підтвердженням email, вхід/вихід, профіль і приватні аватари.
- Створення й редагування клубів, заявки, членство, вихід, архівування та відновлення.
- Книги зі статусами planned/current/completed; голосування за наступну книгу.
- Зустрічі з часовими поясами, приватними деталями та історією скасування.
- Приватні теми й коментарі, редагування, модерацію та soft delete.
- Центр сповіщень, непрочитані повідомлення та генератор нагадувань про зустрічі.
- Адмінпанель: статистику, пошук користувачів/клубів, блокування й модерацію клубів.

Дані та права перевіряються серверними RLS/RPC. Роль admin зберігається в `user_access`, а не в metadata користувача. Звичайний клієнт не призначає ролей. Нагадування з’являються всередині ReadHub; email/push/Telegram-доставку нагадувань не реалізовано. Auth-листи підтвердження — окремий потік Supabase.

## Локальний запуск

Node.js 24 і npm. Із кореня репозиторію:

```text
npm ci
npm run dev
```

Створіть `.env.local` за `.env.example` і задайте URL та publishable key свого Supabase. Секретні server/service_role ключі не додавайте до frontend або `VITE_*`. Після зміни env перезапустіть Vite. У PowerShell, де заблоковано `npm.ps1`, використовуйте `npm.cmd`.

Нова БД потребує міграцій **001–012 у порядку імен** та ручного налаштування Auth: [інструкція Supabase](docs/supabase-setup.md). Уже налаштований робочий проєкт повторно мігрувати чи очищувати для запуску frontend не потрібно.

Опційна контейнерна розробка: `docker compose build`, `docker compose run --rm web npm ci`, `docker compose up`. Це dev-сервер; production збирається окремо. `vercel.json` містить SPA fallback для прямих переходів і F5 на вкладених маршрутах.

## Перевірки

```text
npm run lint
npm run test:run
npm run build
npm run preview
```

Frontend-тести використовують підставні сервіси й не доводять коректність реальної RLS. PostgreSQL/pgTAP та сценарії конкурентності запускаються окремо, лише в одноразовому середовищі: [SQL-тести](supabase/tests/README.md). Фактичні результати та неперевірені сценарії наведені в [журналі перевірок](docs/verification.md).
