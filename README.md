# Книжкові клуби

Вебзастосунок для організації роботи книжкових клубів: каталог клубів з фільтрами,
сторінка клубу, заявки на приєднання (створення, перегляд, редагування, видалення)
з перевіркою полів, маршрутизацією, станами завантаження й помилок.

## Середовище
Node.js: v24.21.0
npm: 11.19.0
Git: 2.45.1.windows.1
Docker: 27.2.0
Docker Compose: v2.29.2-desktop.2
React Router: ^8.4.0
Основний варіант: A (Windows зі стандартними інсталяторами)

## Встановлення й запуск
Нативно:

    npm install
    npm run dev          # http://localhost:5173

Docker:

    docker compose build
    docker compose run --rm web npm install
    docker compose up    # http://localhost:5173
    docker compose down

## Перевірки
    npm run lint         # статичний аналіз
    npm run test:run     # усі автоматичні тести (один запуск)
    npm run test         # тести в режимі спостереження
    npm run build        # виробнича збірка в dist/
    npm run preview      # перегляд збірки, http://localhost:4173

У Docker кожну команду виконуйте як `docker compose run --rm web npm run <команда>`.

## Дані
Джерело даних задає `VITE_DATA_SOURCE` у `.env.local` (шаблон `.env.example`):

- `mock` (за замовчуванням): заявки зберігаються в `localStorage` цього браузера
  під ключем `bookclub.requests.v2`, переживають перезавантаження, не синхронізуються
  між браузерами, пристроями й між адресами з різним портом (dev і preview мають різні сховища).
- `api`: заявки читаються й записуються через `VITE_API_BASE_URL` за контрактом
  `GET/POST/PUT/DELETE /requests`. Адаптер підготовлено, **з реальним сервером не перевірено**.

Каталог клубів (`src/data/clubs.js`) статичний. Секретів у клієнтських змінних немає.

## Можливості
- Каталог: пошук, жанр, формат зустрічей, упорядкування, «лише ті, що читають»; фільтри зберігаються в URL.
- Сторінка клубу з найближчою зустріччю та кількістю поданих заявок.
- Заявки: профіль читача (досвід, формат участі, пошта), нагадування, статистика, фільтри в URL.
- Стани: завантаження, помилка з повтором, порожньо, нічого не знайдено, резервний екран помилки.

## Відомі обмеження
- Дані заявок локальні (див. вище); автоматичної синхронізації між вкладками немає.
- Конфлікти одночасного редагування не виявляються.
- Автентифікації немає: заявка це намір, а не підтверджене членство.
- Для розгортання на хостингу потрібне перенаправлення невідомих шляхів на `index.html`.
