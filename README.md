# Книжкові клуби

Вебзастосунок для організації книжкових клубів: каталог із фільтрами, власні клуби,
заявки на приєднання, вхід і реєстрація. Інтерфейс побудовано як «редакційний»:
книжкова полиця на головній, корінці-кольори жанрів, блоки з мітками збоку.

## Швидкий старт
Демонстраційний обліковий запис на сторінці входу:

- пошта `demo@bookclub.test`, пароль `demo1234` (кнопка «Заповнити демо-даними»).

Можна також зареєструвати власний обліковий запис. Усе зберігається лише в цьому браузері.

## Можливості
- **Гість:** переглядає головну, каталог і сторінки клубів.
- **Користувач (після входу):**
  - створює, редагує й видаляє власні клуби (з попереднім переглядом картки);
  - подає заявки на приєднання, переглядає, змінює й видаляє свої заявки;
  - фільтрує каталог «лише мої клуби».
- **Каталог:** пошук за назвою, жанром і книгою, жанр, формат зустрічей, упорядкування;
  параметри зберігаються в адресі, тому посиланням можна ділитися.
- **Стани:** завантаження, помилка з повтором, порожньо, нічого не знайдено,
  резервний екран помилки.

Захищені сторінки (`/requests/*`, `/clubs/new`, `/clubs/:id/edit`) для гостя ведуть на вхід,
а після входу повертають туди, куди користувач ішов.

## Середовище
Node.js 24 LTS, npm, Git, Docker (за потреби). Версії перевірте командами
`node --version`, `npm --version`, `docker --version`.

## Встановлення й запуск
Нативно:

    npm install
    npm run dev          # http://localhost:5173

Docker:

    docker compose build
    docker compose run --rm web npm install
    docker compose up    # http://localhost:5173
    docker compose down

## Перевірки
    npm run lint         # статичний аналіз
    npm run test:run     # усі автоматичні тести (один запуск)
    npm run test         # тести в режимі спостереження
    npm run build        # виробнича збірка в dist/
    npm run preview      # перегляд збірки, http://localhost:4173

У Docker кожну команду виконуйте як `docker compose run --rm web npm run <команда>`.

## Дані й автентифікація
Усі дані локальні й зберігаються в `localStorage` браузера (залежать від адреси разом із портом,
тому dev `:5173` і preview `:4173` мають окремі дані):

| Ключ | Що зберігає |
|---|---|
| `bookclub.users.v1` | Зареєстровані користувачі (хеш пароля з сіллю, не сам пароль) |
| `bookclub.session.v1` | Ідентифікатор користувача, що ввійшов |
| `bookclub.clubs.v1` | Клуби, створені користувачами |
| `bookclub.requests.v3` | Заявки на приєднання (кожна має власника) |

**Важливо:** вхід це навчальна імітація серверної автентифікації. Хешування паролів
(PBKDF2, SHA-256, 100 000 ітерацій) виконується в браузері, але будь-хто з доступом до
браузера бачить усі дані, тому це не захищає справжні облікові записи. У реальному
застосунку реєстрацію, хешування й сесії виконує сервер.

Режим даних заявок задає `VITE_DATA_SOURCE` у `.env.local` (шаблон `.env.example`):
`mock` (за замовчуванням, `localStorage`) або `api` (REST-адаптер за `VITE_API_BASE_URL`;
з реальним сервером не перевірено). Сервер у режимі `api` має сам визначати власника
заявки за сеансом.

## Відомі обмеження
- Немає синхронізації між вкладками й виявлення конфліктів редагування.
- Заявки бачить лише їхній автор; власник клубу не отримує заявок до свого клубу.
- Початкові клуби каталогу (шість штук) доступні лише для перегляду.
- Для розгортання потрібне перенаправлення невідомих шляхів на `index.html`.
