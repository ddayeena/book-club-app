# SQL-тести ReadHub

Тут збережено 10 pgTAP-наборів і 2 сценарії PostgreSQL isolationtester. Вони перевіряють серверні права й конкурентність, які не доводяться frontend-моками. Факт збереження файлів не є підтвердженням проходження; [статус перевірок](../../docs/verification.md).

## Середовище й запуск

Використовуйте лише одноразову локальну або окрему тестову Supabase-БД. Ніколи не запускайте fixtures в основному ReadHub із демонстраційними даними й адміністратором. Вони створюють фіктивні Auth-записи, змінюють ролі та дати; навіть ROLLBACK не робить їх придатними для production.

Застосуйте потрібні міграції за заголовком набору; ціль фінального регресійного прогону — схема 001–012. Старі позначення 001–005/006 тощо описують історичний базовий рівень тесту, а не доведений результат на фінальній схемі. Перед виконанням перевірте сумісність fixtures із пізнішими тригерами й приватними правами.

Для `*.test.sql` потрібен pgTAP. Виконуйте файли цілком через тестовий SQL-клієнт/pg_prove у підготовленому середовищі. За окремо налаштованого локального Supabase CLI можна використовувати `supabase test db`; CLI-конфігурація та автоматичний тестовий сервер у цьому репозиторії не постачаються. Усі 10 наборів містять транзакцію й завершальний ROLLBACK.

`*_concurrency.spec` — вхідні файли **isolationtester**, а не SQL Editor, pgTAP або Vitest. Потрібні PostgreSQL isolationtester і окрема порожня тестова БД з відповідними міграціями; передайте файл на stdin runner відповідно до його конфігурації з’єднання. Звіряйте очікувані SQLSTATE, кількості та булеві результати з коментарями сценаріїв. Setup/teardown цих сценаріїв можуть фіксувати зміни й видаляти fixtures. Cron у тестовому середовищі не створюйте.

| auth_rls.test.sql | Auth bootstrap, профілі, ролі й RLS |

| club_books.test.sql | Полиця, статуси й права власника |
| book_polls.test.sql | Варіанти, голоси, фіксація й використання вибору |

| club_meetings.test.sql | Розклад, доступ, версії та скасування |
| restore_club.test.sql | Права й незмінність історії після відновлення |
| notifications_reminders.test.sql | Приватність, прочитання, генерація та дедуплікація |

| club_discussions_concurrency.spec | 8 перестановок редагування, видалення та втрати доступу |
